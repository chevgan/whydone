# Third-party notices

whydone ships its CLI as one self-contained JavaScript file: `dist/cli.js` in the npm package and the byte-identical `cli/whydone.mjs` vendored for the Claude Code plugin channel. The build (tsdown) inlines the open-source packages listed below into that file. They are not installed at runtime and the bundled output carries no license headers of its own, so their copyright and permission notices are reproduced here, as their licenses require.

All of them are MIT-licensed except picocolors (ISC). None of them performs network access in whydone.

The list is read off the artifact, not off package.json: rolldown leaves one `//#region node_modules/<package>/...` marker per inlined source file in `cli/whydone.mjs`, and `tests/third-party-notices.test.ts` fails when a package appears in those markers without a notice here, when a notice goes stale, or when a notice's version no longer matches the installed one. Only what is actually bundled is listed: for example js-yaml's `argparse` dependency serves its standalone command-line tool and never enters the bundle. The bundler itself (rolldown, via tsdown; both MIT) also injects a few module-interop helper functions at the top of the file; they are build-tool output, not a bundled package.

Versions are those pinned in `package.json` / `package-lock.json` at the time of the last update of this file.
