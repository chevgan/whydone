# Security Policy

## Supported versions

Only the latest release receives security fixes; there are no maintenance branches for older versions.

## Threat model

The journal is committed to your repo (default storage) — treat entries like code in review. With `storage: local` the journal is hidden via `.git/info/exclude` and never committed, but the same no-secrets rules apply: `whydone publish` can turn any local journal into a committed one later, and hiding never removes entries that already reached git history. The `/log` skill is instructed never to transcribe secrets, but it is not a scanner; review entries in PR diffs. The Stop hook has two delivery channels with the same core: `src/commands/hook-stop.ts` reads git state, writes one JSON file under `.whydone/.cache/`, and interpolates nothing repo-derived into the nudge except two counts. On the npm channel it is invoked as `node <launcher>` via a one-screen generated launcher (`.claude/whydone-hook.cjs`); on the plugin channel it is the one-line command in `hooks/hooks.json` running the vendored `cli/whydone.mjs` (a committed build artifact of `src/`, regenerated by `npm run build` and drift-checked in CI). Audit all three.

## Reporting a vulnerability

Use GitHub private vulnerability reporting (Security Advisories) on `chevgan/whydone`. No e-mail address is listed until a dedicated one exists.

## Expectations

Acknowledgment within 7 days.
